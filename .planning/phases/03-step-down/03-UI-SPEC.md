# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** FALL-02 only. Phase 3 adds ONE swap notice on the existing management UI (`packages/ui/src/pages/home/`) plus ONE indicator in the existing request log. No new screen, no new page, no new nav item (`.planning/research/FORK-SEAMS.md`: "The banner 'Opus is replaced by Sonnet since 15:02'. No new screen."). Every token, component, and pattern below is extracted from the existing UI source and reused verbatim — nothing new is invented.

**Source of truth for this contract:** `packages/ui/src/styles/globals.css`, `packages/ui/src/pages/home/components/layout.tsx` (banner mount + `GatewayStartupErrorBanner` pattern), `packages/ui/src/pages/home/components/network-logs.tsx` (request log), `packages/ui/src/components/ui/*` (shadcn set).

## Phase Surfaces

### Surface 1 — Persistent swap notice banner (management UI)

A new component `SwapNoticeBanner` (place beside `GatewayStartupErrorBanner` in `layout.tsx`), mounted in `MainLayout` directly below the existing error banner slot, so it is visible on every view while a step-down holds:

```tsx
<GatewayStartupErrorBanner … />
<SwapNoticeBanner notice={swapNotice} />   {/* renders null when notice is null */}
```

Geometry (mirrors the error banner exactly):

| Property | Value |
|----------|-------|
| Wrapper classes | `mx-5 mt-3 max-[720px]:mx-3` (existing mount rhythm: 20px side, 12px top) |
| Surface | `network-body-warning rounded-md border px-3 py-2 text-[12px]` — warning amber via tokens, adapts to dark |
| Layout | `app-no-drag flex min-w-0 items-start gap-3` |
| Icon | lucide `ArrowDown`, `mt-0.5 h-3.5 w-3.5 shrink-0` (downward class move; matches error banner icon geometry) |
| Title (line 1) | `font-semibold` — `{Requested} is replaced by {Served} since {HH:mm}` |
| Detail (line 2) | plain 12px — `Serving {model} on {provider} · token {credential} · {reason}`; `truncate` + `title` attr for long ids |
| Safeguards (line 3) | plain 12px, only when the served provider is NOT Anthropic — `Auto mode will not receive Anthropic safeguards from this non-Anthropic provider.` |
| A11y | `role="status"`, `aria-live="polite"` (informational degradation — deliberately NOT `alert`/`assertive`, which is reserved for the error banner) |
| Entrance | fade-in `opacity` 0→1, 150ms, `useReducedMotion` → `reducedMotionTransition` |
| Dismissal | NONE — no close button. The notice disappears only when the higher class has a live triple again (SAFE-02: the user judges aliveness from this notice; hiding it would break that) |

Data contract (backend seam — planner wires it): one read of `packages/core/src/class-switch/notice.ts` exposed as `window.ccr.getSwapNotice(): Promise<SwapNotice | null>` where `SwapNotice = { requestedClass, servedClass, model, provider, credentialLabel, reason, sinceAt, safeguardsApplies }`. Polled by adding one call to the existing `refreshRuntimeStatus` (2s, `startVisiblePolling`) in `App.tsx`, diffed with `preserveEqualPollingSnapshot`. When `window.ccr` is absent (static preview), the banner renders nothing.

Display rules: `requestedClass`/`servedClass` render as capitalized class names (Fable, Opus, Sonnet, Haiku); `sinceAt` renders `HH:mm` (24h, device locale); `model` and `credentialLabel` render in `font-mono`; never render the raw API key — the credential label only (`credentialId`-style label, same redaction as the existing Credential log column).

### Surface 2 — Request log step-down indicator

Two touch points, both inside existing components in `network-logs.tsx`:

1. **Row pill** (desktop `LogRow` + mobile `LogMobileCard`, beside the existing `R{n}` retry pill): when the entry stepped down (requested class ≠ served class), render `SD` pill with classes `network-service-paused shrink-0 rounded px-1.5 py-0.5 text-[10px] font-bold` and `title="Step-down: requested {Requested class}, served {Served class}"`. Non-interactive, exactly like the R pill. Detection derives from existing `RequestLogEntry` fields (`requestedModel` vs `resolvedModel`/`responseModel` class mismatch) — no log schema change.
2. **Expanded detail block** (inside `LogExpandedDetails`, directly above the `network-body-meta` metric grid): a one-row amber notice in the `network-body-warning` style — heading `Step-down notice` (`font-semibold`), then `LogMetric`-style pairs: Requested class, Served class, Model (`font-mono`), Token (credential label, `font-mono`), Reason (from the entry's `routeTrace` decision hops when present). Safeguards line as in Surface 1, same condition. Renders nothing on non-step-down entries.

### Non-visual requirement made visible (no UI work)

Response headers `x-ccr-requested-model` and `x-ccr-served-model` (set at `clientVisibleResponseModel` in `packages/core/src/gateway/request/pipeline.ts` per FORK-SEAMS) appear automatically in the existing response header table (`LogJsonPanel` header tab) once the backend sets them. The UI adds nothing; the contract only asserts they are visible and copyable there — include as a verification item, not a task.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`), pill inner offsets |
| sm | 8px | `py-2` banner vertical padding, `gap-2` pill/metric gaps, `px-2` pill horizontal padding |
| md | 12px | `px-3` banner horizontal padding, `gap-3` banner icon gap, `mt-3` banner top offset |

| 2xl | 24px | Not used this phase |
| 3xl | 32px | Not used this phase |

The banner itself uses only md+sm from the table above.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (banner detail, safeguards, log detail notice) | 12px (`text-[12px]`) | 400 | 1.5 (`leading-[18px]`) |
| Banner title | 12px (`text-[12px]`) | 600 (`font-semibold`) | 1.5 |
| Label / metadata (pill tooltip label, `LogMetric` labels, Requested/Served class labels) | 11px (`text-[11px]`) | 400–600 | 1.45 (`leading-4`) |
| Row pill text (`SD`, `R{n}` family) | 10px (`text-[10px]`) | 700 (`font-bold`) | 1 |

Weights contract: **two weights for all new copy — 400 and 600.** 700 appears only inside the existing 10–11px uppercase pill family (`SD`/`R{n}`), reused unmodified. Monospace (`font-mono`, same sizes) for model ids, credential labels, header values. No new font family, no size outside {10, 11, 12, 13}px in this phase (10px only via the existing pill pattern).

Do NOT use `Badge variant="warning"` (hard-coded light-only amber) for the banner or the detail block — it breaks in dark theme. Token-based classes only (`network-body-warning`, `network-service-paused`).

## Copywriting Contract

Primary CTA: **none** — the notice is state, not an action; no button on the banner (removal is automatic, not user-driven).

| Element | Copy (en source key) | zh |
|---------|----------------------|-----|
| Banner title | `{Requested} is replaced by {Served} since {HH:mm}` — e.g. `Opus is replaced by Sonnet since 15:02` (canonical example from FORK-SEAMS) | `自 {HH:mm} 起，{Requested} 由 {Served} 代答` |
| Banner detail | `Serving {model} on {provider} · token {credential} · {reason}` | `服务模型 {model}（{provider}）· 令牌 {credential} · {reason}` |
| Banner safeguards line | `Auto mode will not receive Anthropic safeguards from this non-Anthropic provider.` | `非 Anthropic 供应商不提供 Anthropic safeguards，auto 模式将不会收到该字段。` |
| Row pill | `SD`; `title="Step-down: requested {Requested class}, served {Served class}"` | `title="降级：请求 {Requested class}，实际服务 {Served class}"` |
| Log detail heading | `Step-down notice` | `降级提示` |
| Log detail safeguards line | same as banner safeguards line | same |
| Empty state | none new — banner absent = all classes healthy; request log keeps its existing empty states (`No request logs yet.` etc.) | — |
| Error state | none new — a failed `getSwapNotice()` renders nothing (same as no data); the FALL-03 all-classes-empty error surfaces through the existing request-log error row treatment (`network-error-box`), not new UI | — |
| Destructive confirmation | none — no destructive action in this phase | — |

`{reason}` comes from the notice state (e.g. "no live Opus triple"); it is a short phrase, lowercase-start, no trailing period in the detail line. Never include API keys or message bodies in any notice copy (SAFE-01: scalars only).
